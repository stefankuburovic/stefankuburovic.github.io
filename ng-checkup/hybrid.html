Migration plan: AngularJS 1.5.9 → Angular 22

4 phases, each shipping on its own, in the order of the Angular upgrade guide: prepare on AngularJS, run both frameworks side by side, move the code bottom up, remove AngularJS.

  1. 1Prepare on AngularJS

    The AngularJS code is made of components and services, written the way Angular expects them; it still ships on AngularJS alone.

    • Upgrade AngularJS to 1.8.3npm install angular@1.8.3 angular-animate@1.8.3 angular-resource@1.8.3 angular-route@1.8.3 angular-sanitize@1.8.3

      The last release; read the migration notes of each minor on the way.

    • Bring TypeScript into the AngularJS code 35

      Rename the files to .ts, add @types/angular, and tighten types file by file. Services written in TypeScript move to Angular almost unchanged.

    • Turn controllers into components 88

      Explicit bindings instead of an inherited scope, and no more ng-controller in templates (83). Only components cross the border between the two frameworks.

    • Reshape directives that use compile, replace or terminal 5

      UpgradeComponent cannot wrap them.

    • Move state off $scope 20

      controllerAs and bindToController, so the controller is the component class it will become.

    • Replace scope events with services 64

      A service with an RxJS Subject instead of $broadcast/$emit; it later carries the messages across the border.

    • Turn ng-include templates into components 27
  2. 2Hybrid setup

    Both frameworks run on one page, and new features are written in Angular.

    • Bring the Angular side up to 22 18

      New code should be written on a current Angular. The upgrade plan below lists each ng update step; @angular/upgrade moves with @angular/core.

    • Let the two routers share the URL 25

      ngRoute keeps the AngularJS routes, the Angular Router takes over route by route; setUpLocationSync from @angular/router/upgrade keeps both in step.

  3. 3Move piece by piece, bottom up

    Every service, component and template is Angular code; each step ships on its own.

    • Move services to Angular, oldest dependencies first 33

      Each becomes an @Injectable and stays available to AngularJS through downgradeInjectable until its last AngularJS user is gone.

    • Turn filters into pipes 16
    • Move components and directives, leaves first 115

      A rewritten component is used from AngularJS through downgradeComponent; an AngularJS component still needed inside Angular is wrapped with UpgradeComponent for the time being.

    • Rewrite the templates in Angular syntax 178

      ng-repeat becomes @for, ng-if becomes @if, ng-model becomes a form control or a model input, ng-click an event binding.

    • Replace runtime $compile with dynamic components 4
    • Replace $watch with signals 85

      computed for derived values, effect or an input for reactions.

    • Replace angular-route

      With the Angular Router.

    • Replace angular-resource

      With HttpClient.

    • Replace angular-animate

      With CSS transitions, or @angular/animations.

    • Replace angular-sanitize

      With Angular's built-in sanitization.

    • Replace angular-translate

      With @ngx-translate/core, or @angular/localize.

    • Replace angular-strap

      With @ng-bootstrap/ng-bootstrap or ngx-bootstrap.

  4. 4Remove AngularJS

    One framework, one build, one change detection.

    • Move the last routes to the Angular router 25
    • Remove the downgrade and upgrade wrappers 30

      Nothing on the AngularJS side uses them any more.

    • Bootstrap Angular alone and uninstall AngularJSnpm uninstall angular @angular/upgrade angular-animate angular-resource angular-route angular-sanitize angular-translate angular-strap

      Drop UpgradeModule and the AngularJS bootstrap; the bundle loses AngularJS and the second change detection.

  • HighAngularJS 1.5.9 is end of life since January 2022

    Google ended AngularJS support on 31 December 2021: no security fixes, no fixes for new browsers, only paid third-party extended support. Nothing in AngularJS carries over to Angular; every controller, directive, service and template is rewritten or wrapped, which is why the migration goes piece by piece, with both frameworks running side by side in between.

  • LowMove to AngularJS 1.8 before anything else (now 1.5.9)

  • HighstrictNullChecks is off

    Every value that may be null or undefined is typed as if it never is, so the most common runtime error in an Angular app is invisible to the compiler. In a large codebase switching it on is staged: a separate tsconfig that checks one folder at a time, with a count that may only go down.

  • HighstrictTemplates is off

    Template bindings are only loosely type-checked: a wrong input type, a misspelled output payload or a possibly-undefined value passed to a component compiles and fails at runtime. Turning it on typically surfaces a batch of real bugs alongside the type noise.
