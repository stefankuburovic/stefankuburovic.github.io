  • HighPrimo VE customizations do not carry over to NDE, announced as the only Primo UI from January 2028

    The New Discovery Experience is extended through an Angular custom module (ExLibrisGroup/customModule, Angular 18), where each customization is an Angular component mapped to an nde-… selector in selectorComponentMap. There is no hybrid route as for an AngularJS app: the package is rebuilt hook by hook, and it can be developed against the live view with the module's proxy mode before go-live.

  • Medium22 Primo hooks to rebuild, with 5 helper components

    Each prm-…-after/-before slot the package fills becomes an Angular component in the custom module, mapped to the matching nde-… selector; NDE's names follow its own layout, so each slot's counterpart is found in the NDE UI first. Hooks used: prm-action-container-after, prm-action-list-after, prm-advanced-search-after, prm-atoz-search-bar-after, prm-blank-ill-after, prm-brief-result-after, prm-explore-footer-after, prm-facet-after, ….

  • MediumparentCtrl read in 11 places

    parentCtrl is the VE hook's handle on the internal AngularJS controller of the Primo component it extends. NDE has no such controller: a custom component gets hostComponent (the Angular component instance, with a different shape) and reads the app state through NgRx selectors. Each read is found again there, and it is where most of the effort and the risk of a hook sits. Read most: actionName (3), searchStateService.searchObject (3), item.pnx (2), facetGroup.facetGroupCollapsed (1), facetGroup.name (1), term (1).
